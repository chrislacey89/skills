## v1.20.10 — the landing page's canon stops being a list somebody maintains (#273)

The canon section is a router pointing at provenance: it shelves a set of works and tells the reader *"each SKILL.md names its sources in frontmatter."* The set was a hand-written array in `site/src/lib/data.ts` with nothing relating it to the `sources:` blocks it claimed to represent, so the two drifted in both directions and in silence. #272 caught one direction — a spine attributed to `/ts-audit`, which declared no `sources:` block at all. This is the other, and it is larger: the shelf held **8 of the 45 works the skills actually cite**. *Thinking in Systems* is named by nine skills and was not on the page. Neither failure emits a signal — the page builds, the spine renders, the book opens.

Four works were also declared under two author spellings each, with `/closeout` alone carrying three of the four minority spellings. That matters more than it reads: grouping is by the whole declared string, so a second spelling splits one work into two entries and halves each half's citation count. Before this change the 49 distinct declared strings named only 45 distinct works and nothing collapsed them; there are now 45 strings naming 45 works.

### Changes

- **`scripts/generate-canon.sh` derives the canon and writes `site/src/lib/canon.generated.ts` (#273)** — one entry per distinct declared work, carrying the verbatim string, its parsed title and author, a type, and every citing skill with the tier it cites under. 45 works, 98 citation edges, nothing hand-listed. A committed generated file rather than a build-time read, because the canon has to be importable from `Shelf.astro`'s **client** script, which cannot touch the filesystem, and because this repo's checks are shell suites that run without installing the site's `node_modules`. `--check` regenerates into memory and diffs, so a stale copy cannot reach prod.
- **Author aliases are normalized at the source, not collapsed by a table (#273)** — the issue offered both. A table is itself a hand-maintained canon list, which is the defect under repair, and it mis-collapses silently the first time a new variant appears. The four live pairs were normalized to the majority spelling (`Andrew Hunt & David Thomas` breaks the one 1–1 tie, matching how the repo spells its other two-author entries), and the suite gained a **collision detector**: no title may be declared under two different author strings anywhere in the repo. A rule fails loudly where a table fails quietly.
- **Papers are typed from their own citation convention — plus an escape hatch that turned out to be needed (#273)** — `et al.`, or a trailing parenthesized four-digit year. A list of paper titles would drift. A book carrying `(Second Edition)` is not caught by it, which is the trap a parenthesis-only rule falls into and which has a fixture. But review found the rule's blind spot with a live instance: `/walk-commits` cites *Peer Review on Open-Source Software Projects — Peter C. Rigby*, a research paper by a single author with no venue or year in the string. **There is no truthful tell to read**, so it typed `book` and the spread labelled a paper "From the book". The affordance the first draft named as hypothetical is now built: an optional `papers:` sub-key under `sources:`, declared by the skill that cites the work — because that skill is the thing that knows what the work is. A marker adds a type, never a citation, and every marker must name a work the same skill declares under a tier.
- **The type oracle was re-deriving the generator's rule, so it could never disagree (#273)** — it recomputed `paper` iff `et al.` or a trailing year, over the same author field, and its comment claimed it asserted "the property, not the rule." It was the rule. That is why the Rigby mistype was green. Correctness now comes from `EXPECTED_PAPERS`, a list written by hand in the suite — **and a hand-written list is the right answer here for exactly the reason it was the wrong answer for aliases and for paper titles in the generator.** `mutate-the-oracle-not-only-the-subject-2026-08-19.md` requires the oracle to be capable of disagreeing with the subject; a predicate recomputed from the subject's input cannot, and a list somebody wrote down can. Adding a new paper turns it red until a person confirms the classification, which is the check working.
- **`Shelf.astro` renders all 45, with spine height mapped from citation count (#273)** — the page can finally make a claim it always had the data for. Ordering is heaviest-first then alphabetical, and it lives in the component rather than the generated data, so **#274 can revisit it without touching the derivation**. Giving 45 spines their proper form — a bookcase rather than one wrapped row — is #274's work and is deliberately not attempted here.
- **The opened spread is derived, and it had to be (#273)** — eight hand-written spreads across 45 spines means 37 books that open to nothing. The left page carries title, author and a provenance line read off the citations (*"Cited by 9 skills — 1 primary, 8 secondary"*); the right page lists every citing skill with its tier and a link; and the `sources:` snippet is **composed from the canon rather than transcribed** out of the file it describes. A transcription is what went stale in the first place.
- **`bookDetails` becomes `lessons`, and it is optional on purpose (#273)** — the eight hand-written pull-quotes, keyed by canonical work, and nothing else. **The suite asserts nothing about its coverage**, so a work with no lesson opens to its derived spread and a missing lesson can never keep a newly declared source off the page. That is what makes 45 maintainable: curation stays possible without becoming mandatory, and the part that must be complete is the part a script generates. What *is* pinned is that no lesson is keyed to a work nobody declares — #272's shape one layer in.
- **`scripts/test-canon-coverage.sh` is rebuilt around what a derivation can get wrong (#273)** — the shelf-side checks went with the array they parsed. That is not lost coverage: #272's property is now checked on **every** citation edge rather than on the one skill a hand-written entry named, which is strictly stronger. What replaces them: byte-exact freshness, set equality in both directions, the type **property** re-derived rather than the generator's rule re-implemented, citation edges checked forward *and* backward, and `data.ts` naming a declared work only inside the `lessons` block.
- **The reverse citation direction is not redundant (#273)** — dropping one citation from a work with other citers leaves the work shelved and every forward edge sound. Nothing looks broken; only the citation count is understated, and #274 renders that count as spine height. Its fixture asserts the forward check does *not* fire there, so the two directions cannot silently collapse into one.
- **A `canon-render` CI job builds the site and re-runs the suite against `site/dist/index.html` (#273)** — every other check in the file reads source and reasons about what it would produce. This one reads what *was* produced, which is the difference between "the component imports the canon" and "the reader can see all 45 works" — and #273 is a bug report about the second. It **SKIPs locally with a visible line** rather than passing silently. The `.slice(`/`.filter(` tripwire beside it keys on a language construct, which `mechanism-generality-lags-the-pattern-2026-08-23.md` is explicit is the weaker kind of detector; the file says so rather than letting it read as the mechanism.
- **`generate-canon.sh --check` is wired into lefthook pre-commit (#273)** — sub-second, and it catches the one case at the moment it happens: a `sources:` block changed and the canon was not regenerated.
- **Two mutations escaped the first battery, and both were real gaps rather than fixture mistakes (#273)** — a ghost spine in the built page went unflagged because the mutation never landed (the selector patched carries an Astro scope attribute, and nothing asserted the edit applied). And a hand-written shelf array restored into `data.ts` went unflagged because the check asked whether each named work was *also* a `lessons` key — and **the eight lessons are exactly the eight works the old shelf held**, so a straight revert names only works that are already keys. The check was green on the precise regression it exists to catch. Rewritten to ask *where* the string appears rather than whether it appears elsewhere, with a fixture pinning that exact shape.
- **Eleven oracle mutations across the two commits (#273)** — a collision detector reporting every title (47 false reds) and one reporting none; a title split on a fixed substring; variants dropped from the failure row; a canon extractor returning nothing; a slot counter that counts nested citation objects; a type check that accepts everything; a forward-edge check that never reports; a reverse check comparing the frontmatter against itself; the frontmatter terminator removed; and the stray-mention scope inverted. Each produced its own targeted failure. `mutate-the-oracle-not-only-the-subject-2026-08-19.md` is why the oracle half was run at all, and it is what found the second escaped mutation above.
- **Also fixed: the failure message ate the `&` in four authors' names (#273)** — it was built with a `sed` replacement, where `&` is the whole-match backreference.
- **Deliberately unchanged (#273)** — the `mappings` array and its checks, which are a separate hand-authored provenance claim on the same page and are still pinned by title; the section's visual identity, which is #274's subject; and the `lessons` prose itself. No new pull-quotes were written — inventing an editorial summary of a book is authorship, not derivation, and this change is about removing hand-maintenance rather than adding it.

## v1.20.9 — the pack could say how to test a wrong value and never how to make it unbuildable (#268)

#266 shipped the review-time half of a defect: `pre-merge/review-checklist.md` Dimension 6 now leads with the type-level fix and demotes per-provenance runtime guards to the fallback. Nothing in the pack told an implementer how to *build* it that way, which is where the cost is lowest. Verified before this change — `rg -in "illegal state|smart constructor|parse, don't validate|branded type|unrepresentable" tdd/ execute/ pre-merge/ write-a-prd/` returned nothing outside that one review bullet. `tdd/` ships six reference files and none of them reached the technique; its `sources:` carried Ousterhout, Fowler, Beck, Khorikov, Freeman & Pryce, and Ammann & Offutt, and no Wlaschin.

The field incident is #266's, read one layer down. A downstream verbatim-quote checker — the guard against a model inventing a quote it claims to have found on a page — was widened from the page's extracted reading text to its raw HTML. Correct and measurement-backed, but both values are plain `string`, so the *contract* never widened with the behavior and a fabricated quote colliding with a script body, an HTML comment, or a URL inside an attribute now passes the check whose entire job is catching fabrications. The parameter was renamed `pageText` → `haystack` in the same diff. **That rename is the part worth sitting with: it did not merely fail to document the precondition, it deleted the only place the precondition was recorded.**

The pack was well covered on making a wrong value *fail a test* and uncovered on making a wrong value *impossible to construct*. Those are different interventions at different costs, and the second is strictly stronger where it applies — *"because a runtime check only protects the one call site it guards. Every other function that touches the value has to independently re-check it or silently trust an unenforced convention — and conventions get forgotten."* (Wlaschin's argument, in the library reference file's paraphrase — not a quotation from the book.)

### Changes

- **A fourth rule in `tdd/interface-design.md`: *Make an illegal input unconstructable, not merely detectable* (#268)** — the technique's one canonical home, reached from `/tdd` Step 1 Planning, which is *before* any code exists and therefore the cheapest moment. It carries the Wlaschin quote, the TypeScript translation (branded type + single constructor, discriminated union, `z.string().brand<…>()`, unbuildable shapes for cardinality rules), a four-row table selecting the shape by what the callee has to do, and the construct-once-at-the-boundary rule with its corollary that a defensive re-check downstream is not extra safety but a re-teaching that the type cannot be trusted.
- **The trigger is narrow, and deliberately so (#268)** — *a parameter's accepted input domain widens while its type does not*, whose sharpest diff signal is a rename from a domain-specific parameter name to a neutral one (`pageText` → `haystack`, `userEmail` → `value`). This is visible in a diff and does not require judging every primitive in the codebase, which is the version of this rule that would have been ignored.
- **What it does to the tests, because that is why it belongs in `/tdd` at all (#268)** — a whole category disappears: you do not test that a function rejects an out-of-range value, because the type rejects it before the test would run. What gets tested instead is the constructor. One test at the boundary replaces N tests at N call sites — the same trade the technique makes in the production code.
- **The proportionality bound ships with it (#268)** — *"This is not 'brand every primitive.'"* Wlaschin calls one maximal form of the trick — F# units of measure — *"probably design overkill"* for his own domain, and frames the guideline as proportionate use of one trick. #268's Non-Goals named the failure mode precisely: a rule that reads as "wrap every string" will be ignored or, worse, followed. It is one sentence, it is the most deletable thing in the section, and the contract test pins it.
- **The second, separable lesson lands in `tdd/refactoring.md` § Discipline (#268)** — *change the type first, then let the compiler enumerate the call sites*. The `haystack` change did the exact inverse: widened the caller, left the model alone, renamed the parameter so nothing flagged the mismatch. Wlaschin Ch. 13 turns that into a build error at every call site. **Its precondition ships in the same paragraph** — this works only with total functions over closed types; a widened `string`, an `any`, an added optional field, or a `switch` with a permissive `default` gives the compiler nothing to flag. #268 asked for that precondition explicitly, *"or the rule gets cargo-culted into codebases where it does nothing"*, and it is the only part of the rule whose absence is silently harmful rather than merely absent.
- **…and it had to be reconciled with a rule already in the file (#268)** — *change the type first* deliberately breaks the build, which reads as a contradiction of `/tdd`'s *never refactor while RED*. A short paragraph now distinguishes the two: a red bar is a failing test, meaning behavior is missing; a broken build here is an in-progress mechanical migration with no behavior change in it, finished in one step, after which the tests go green unchanged. If getting the build green turns out to *require* new behavior, the next rule in the file already covers it. Review caught that the reconciliation had been written into `refactoring.md` while the rule it reconciles lives in `tdd/SKILL.md:134` — a *different file*, so a reader who hits the flat prohibition mid-refactor and never opens `refactoring.md` got the contradiction and not the resolution. `SKILL.md:134` now carries the exception and a pointer to it.
- **No seventh reference file in `tdd/` (#268)** — the issue's first open question, and the answer is that the two lessons belong at two different moments, not in one new file read at neither. The construction-time technique goes where the reader is deciding parameter shapes; the change-time move goes where the reader is refactoring. `tdd/SKILL.md`'s Planning checklist and `refactoring.md`'s *Primitive obsession* candidate both now route to the former, so it is reachable from the two paths that arrive at it.
- **`/execute` Step 3 gets nothing, and that is a decision rather than an omission (#268)** — the issue's third open question. Step 3's job is classification, and it routes backend and behavior-heavy work to `/tdd`, which now carries this at both the design moment and the refactor moment. Its one existing TypeScript rule is there because `satisfies` is a *mechanical* trap with a one-line fix; this is a design judgment that needs its proportionality bound and its selection table to be applied correctly, so a Step 3 one-liner would be precisely the "wrap every string" cargo-cult the Non-Goals forbid. Step 3 is a high-traffic surface and the addition did not clear its own bar.
- **`tdd/SKILL.md` gains Wlaschin under `sources:` (#268)** — two of its reference files now quote him. `CLAUDE.md` § Editing Skills forbids claiming a source the body does not operationalize; the inverse drift, operationalizing one and never declaring it, is what this closes.

## v1.20.8 — `/compound` gets an outbound artifact channel, so a pack-level lesson can stop being prose (#266)

#257 gave `/compound` a rule with teeth: a second recording of a known pattern must ship a mechanism, and *"a third prose-only entry on the same pattern is not a valid outcome."* This ships the thing that rule needed to be satisfiable. **All four of its permitted mechanisms — a test, a linter rule, an assertion, a planning checklist item — are artifacts of the downstream project.** When the change that would prevent the next instance is a change to a *skill*, there was nothing legal for the lesson to become, so it fell back to prose. The rule fired correctly and produced nothing.

The field evidence is a downstream TypeScript repo whose verbatim-quote checker — the guard against a model inventing a quote — was widened from a page's extracted reading text to its raw HTML. Correct and measurement-backed, but the function's contract never widened with it, so a fabricated quote colliding with a script body, an HTML comment, a structured-data block, or a URL inside an attribute now passes the check whose entire job is catching fabrications, and the UI reports it as *"quote found on the page."* The parameter was renamed `pageText` → `haystack` in the same diff — the widening made visible in the signature and then not acted on — and the remedy was already imported at the top of the same file, where a sibling function 165 lines above wraps the identical value in a discriminated union first.

That repo's `docs/solutions/` already held an entry for the pattern, **written sixteen days earlier**, whose Prevention named a change to the review skill. ## v1.20.7 — `/compound`'s promote-to-mechanism rule stops disarming itself (#257)

`CLAUDE.md` § *Commands a skill documents* closes with the line that names this whole failure: **"Careful reading is not the mechanism."** Eight `scripts/test-*.sh` suites enforce it here. ## v1.20.6 — `/triage-issue` names regressions as a trigger and now has a regression procedure (#236)

`/triage-issue` is the pack's deep-debugging skill. Its `description` and its Invocation Position both name **"the bug is a regression"** as a reason to reach for it. It had no procedure for that case. `rg 'bisect'` across the repo returned exactly one hit — `pre-merge/review-checklist.md`, where the word appears only as a *rationale* for keeping commits atomic, never as something anyone runs. The pack protected bisectability and never bisected.

That gap is sharper than a missing nicety, because the skill's best design decision is already the hard part of closing it. Step 2 forces a deterministic reproducing loop into existence before any hypothesis work — *"the highest-leverage activity in this skill — every later step is guessing without it."* That loop is precisely the oracle `git bisect run` needs. The skill built the tool and then, for the one bug class where history already holds the answer, put it down and read code instead.

The audit that produced this started from Tornhill's *Your Code as a Crime Scene* and **nothing from Tornhill survives**. Hotspots and churn were withdrawn against relative-churn (a `uniq -c` recipe does not compute it) and against the Gamma trap (Erich Gamma ranked second-highest in defect density at Eclipse because senior developers are assigned the riskiest work). Change coupling was rejected on mechanism: the pack's three existing sibling-defect seams search for *pattern similarity*, while co-change finds *files edited together*, and those are different sets. Everything that shipped came from Andreas Zeller — a source `/triage-issue` already declared. The transferable lesson is the method, not the material: **checking a skill against its own declared source** was the highest-yield move in the audit, and it is what killed most of the proposal.

### Changes

- **A regression branch in Step 2, placed before the code-reading trace (#236)** — when the bug is a regression and a last-good reference exists, hand the Step 2 loop to `git bisect run` and let history answer instead of reasoning toward it. It sits after the loop gate and the Heisenbug paragraph and before the Explore trace, so the failure-inducing change becomes an *input* to that trace rather than something the trace has to rediscover. Zeller § c.
- **The result is framed as evidence, not a suspect (#236)** — the failure-inducing change says when the infection entered, not which line is defective, and the change that introduces a latent defect is often not the one that made it observable. The instruction is to carry the diff into the trace as a fact and keep tracing backward from the failure, which is what keeps the branch compatible with Zeller § f rather than in tension with it.
- **Four riders, each of which is the difference between a useful clause and an overpromise (#236)** — check the oracle's polarity at both ends before starting; squash-merged history yields a first-bad **PR**, not a first-bad commit, so report a narrowed diff and not a single line; a nondeterministic loop breaks the oracle, because bisect trusts every verdict it is handed and a flaky loop will confidently name an innocent change; and no known last-good state means skip and say so, never guess a range, since a bisect from an invented `good` ref returns its answer with exactly the confidence of a real one.
- **The polarity rider is the fourth, and it was added because review found the defect it describes in this PR's own fixture (#236)** — Step 2's loop is a *reproducing* loop, so "the loop passes" reads two ways: *the bug is gone*, which is what bisect needs, or *the reproduction succeeded*, which is the natural shape for a script written to demonstrate a failure. Hand bisect an inverted or a constant oracle and it still terminates and still names a commit — an innocent one, reported with exactly the confidence of a correct answer. The rider asks for two commands: run the loop on the known-bad and known-good refs and confirm non-zero and zero. An earlier draft of this entry claimed the inverted case names the commit that *fixed* something; that is wrong, and a verification pass caught it by building the history and running it — in a regression range there is no fix commit to name, and git returned an unrelated one.
- **The dangling "prior incident patterns" phrase is defined (#236)** — Step 2's ranking clause asked the agent to rank on prior incident patterns and never said where one is found, so the instruction was either unhonored or filled with whatever the agent invented. It now means prior fix commits touching a candidate path, read from the **commit log** rather than the issue tracker — which is what keeps it clear of the template's standing prohibition on file paths and line numbers.
- **That count ships bound by two conditions and a gate, all stated in the text (#236)** — **confirmatory, never generative**, so it may only reorder candidates the failure trace already nominated and must never nominate one (this is what satisfies Zeller § f: a file's history is evidence about a candidate in hand, and becomes suspicion-led search the moment it puts a file on the list); **best-effort**, so absent a fix-commit convention the count is noise and the step is skipped rather than ranked on; and the Gamma gate, requiring the mechanism be named in one line — "three prior fixes here, all null-guards at the same boundary" — before any reordering happens.
- **All four documented commands are pinned by an executable contract test (#236)** — `scripts/test-documented-git-commands.sh`, wired into `validate-skills.yml` and `lefthook.yml`. This is CLAUDE.md § "Commands a skill documents" rule (b) applied to its own trigger: #243 shipped six successive drafts each carrying a wrong claim about a git subcommand, every wrong draft was caught by a human or a review sub-agent, and none by a check. The suite extracts each invocation verbatim from `triage-issue/SKILL.md` rather than restating it, then *runs* it — the fix-commit grep against a synthetic repository carrying one commit per alternative in the pattern plus a non-matching commit and a matching commit outside the candidate path, and all three lines of the bisect block against a planted regression. The fixture is hermetic in both directions: `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` are neutralized so a contributor's personal git settings cannot redden it, and it plants its own history because `actions/checkout@v4` clones shallow, so any assertion about this repo's own commits would pass locally and fail in CI for reasons unrelated to the command under test.
- **The suite's oracle is checked at both ends, because the first draft's was not (#236)** — this is the review finding worth recording, and it is the one this changelog previously got wrong. The first draft's bisect oracle was `grep -q ok value.txt` against a fixture that wrote `broken` to mark bad revisions — and `broken` contains `ok`. The oracle answered "good" on every revision, bisect walked to HEAD, and the suite reported green: one assertion found the planted SHA in git's intermediate `Bisecting: … [<sha>]` checkout line, and a separate assertion found the phrase `is the first bad commit` attached to a *different* SHA. Neither bound the SHA to the answer. Four mutations of the *command* went red against that draft, which is exactly what made it look verified — they all made bisect abort outright, so they proved the suite catches a crash and never that it catches a wrong answer. Fixed three ways: a whole-line oracle (`grep -qx`), a single assertion binding the SHA to the phrase, and a pre-flight that runs the oracle on both known ends and fails if it answers the same at each.
- **The documented grep pins its regex dialect (#236)** — `git log --grep` honors the `grep.patternType` config key, so the original escaped-alternation pattern returned **zero matches** for any user with it set to `extended`, `perl`, or `fixed`. Zero is the dangerous answer rather than a loud one, because the skill's own "best-effort" bullet reads it as "this repo has no fix-commit convention" and skips the step — a wrong answer wearing the skill's sanctioned exit. The command now passes `-E` explicitly, and the suite runs it under each hostile dialect and requires it to keep matching.
- **Rule (a) applied before rule (b) (#236)** — the skill points at `git bisect --help` § "Bisect run" for the exit-status contract instead of paraphrasing it. Restating which codes mean good, bad, and untestable would be a permanent drift liability this repo would then own, and the cheapest command claim to keep accurate is the one not made. ## v1.20.5 — The pipeline gets a format for its own N-way forks (#245)

Skill Kit manufactures multi-option forks structurally. `/design-an-interface`'s entire output is N candidate interface shapes. `/api-design-review` weighs REST against RPC against GraphQL. `/improve-pipeline` returns a four-way verdict. `/pre-merge` presents every finding against a four-way disposition. The user read the prose and replied "pause." Redrawn as parallel columns, three things surfaced that prose had not: a factual error in one option's cost list, one option that was **dominated**, and a fourth option nobody had listed. Domination is invisible in prose by construction — it is a relation *between* options, and prose never shows two at once.

### Changes

- **A tenth block in the rendering core's vocabulary, `options-comparison` (#245)** — N mutually exclusive options as identical panels in one eyespan. The markup (`docs/visual-recap-design.md` §11) is a **matrix**: attributes as rows, options as columns, the row label written once on the left. Cells in a band are grid siblings, so they stretch to the tallest and stay aligned, which is what makes it an eyespan rather than a scroll. A missing option shows as empty space; a dominated one shows as a column that pays in every band.

## v1.20.2 — The deferred rebuttal round ships, in the shape the sources actually support (#217)

v1.20.1 shipped half of #217 and deferred the other half. The deferred half was a **rebuttal round**: each role reads the other's opening case and replies, and the Mediator rules on all four. It was held back behind a one-run trial because its failure mode looked invisible from inside a single run — the two agents converging instead of sharpening, each conceding the other's frame, handing the Mediator a worse input at higher cost while the verdict still read fine. That risk was named *degeneration-of-thought* and attributed to two arXiv papers **that had not been read**. `/pre-merge` caught the secondhand attribution and marked the deferral provisional under `docs/solutions/architecture-decisions/secondhand-source-proposal-specificity-2026-08-11.md`.

The papers were acquired and read. Degeneration-of-thought is a property of **self-reflection** — *"once the LLM-based agent has established confidence in its answers, it is unable to generate novel thoughts later through self-reflection even if the initial stance is incorrect"* (Liang et al., p. 17889) — and debate is the paper's **cure** for it. The deferral had named the correction as the risk. The fear itself was real but belongs to Du et al., who call it *sycophancy*: an agent writes that a peer's answer is wrong, then adopts it anyway.

So the trial ran, and it ran on the real staging: opening cases spawned in one message, replies sent simultaneously, then **two independent Mediators** — one given only the opening pair, one given all four — spawned together so neither saw the other's verdict. Both returned the same verdict. One thing moved, and it is the whole reason this round ships: the Skeptic's reply argued that the Advocate's proposed trigger asked the Mediator to *notice itself* about to argue, which is the failure `SKILL.md`'s own "discipline-shaped fix in disguise" classifier exists to reject. The second Mediator accepted it and replaced the trigger with a mechanical one. **The round caught the proposal violating a rule the skill already carried, and the round-1 pair did not.**

### Changes

- **The Mediator gates the reply round on attribution, not introspection (#217)** — before writing a verdict it attributes every decisive point to quoted text from one of the two cases, and calls one reply round when a decisive point has no source, or when the cases contradict on a checkable fact. Otherwise it records **no reply round** and rules. This is the shape the sources support: Liang's adaptive break, where the judge stops as soon as it has enough, and where *forced* continuation past that point measurably **harms** results rather than merely wasting tokens. A mandatory round — #217 as filed — is the one configuration both papers say not to build.
- **Replies are bounded, quoted, and discardable (#217)** — sent in a single message so the replies inherit the opening cases' independence; each quotes the specific claim it answers, says what it concedes *and* what still stands, and stays under 250 words. The clause that carries this is *"the roles need not agree; the objective is the right answer rather than the win"* — forced consensus collapses the exchange into mutual confirmation and maximal disagreement turns it into a contest, but naming either forbidden behavior in the skill would only make it more available, so the text states the target and not the two ditches. A reply that concedes without quoting a claim is **discarded** and the verdict is written from the opening pair — that reply is the failure this round is most likely to produce, and it reads exactly like a good one.
- **Two no-op sentences are cut from the role specs (#217)** — *"The Advocate should optimize for better real-world outcomes, not for defending current structure"* and *"The Skeptic should assume the cost of a bad pipeline change compounds across future usage."* Both fail `docs/skill-anatomy.md`'s no-op test; the first is negative framing the same doc warns against, the second restates the bullet directly above it. The Advocate and the Skeptic agreed on both cuts. Net for the whole change is +7 lines on a skill #68 has flagged for size.
- **The decision is recorded, so dead ceremony is detectable (#217)** — replies append under the existing `## Advocate Case` / `## Skeptic Case` sections as `**Reply:**`, and a Verification bullet requires the issue to record which of **four** outcomes occurred — replies kept, reply discarded, no reply round, or degraded mode. Four rather than two because the round has four terminal states, and collapsing them loses the two that matter most: a discard is the failure the round is designed to catch, and degraded mode never had a gate to fire. Only *no reply round* counts as a gate non-fire, so the falsification test stays readable — if ten runs pass with no trigger, delete the round.
- **Deliberately unchanged** — the three roles, the four verdicts, and the Mediator's source-reconciliation duty; the parallel opening cases from v1.20.1; the single shared model across all three roles, which Liang names as one of two bias-safe judge configurations and which should not be "fixed"; every other skill.
- **Not addressed, and named as such (#217)** — the Mediator's own novel arguments are still unrebuttable by construction. The attribution gate reaches this *partly*, since an unattributed decisive point now triggers a round in which the roles see the argument before it lands, but the final synthesis remains unanswered. Two cheaper levers also stay unpulled and are filed separately: **persona diversity** (Du: MMLU 71.1 → 74.2) and **cross-model roles**. Phase 4's roles differ by stance and never by perspective.

## v1.19.1 — The review-currency stamp becomes a contract the repo can check, not prose two skills happen to agree on (#184)

v1.19.0 shipped a marker string that spans two skills — `/pre-merge` Phase 4 writes `<!-- reviewed-at: <sha> -->` into the PR body, `/closeout` Step 2 reads it back and compares it to `headRefOid` — with no shared definition of the string's shape. The writer emitted a full 40-character SHA and said so; the reader accepted 7 to 40. `headRefOid` is always 40 characters, so a short SHA reaching that marker would parse successfully and then compare unequal *forever*: `/closeout` reporting divergence on a PR whose head had not moved. No incident yet; this was found by reading the two halves against each other while scoping #182. The failure would have been silent and self-reinforcing — a second false-positive source in a gate that #163 had already been bitten by one false positive on, training exactly the reflexive click-through #163's own Skeptic Case warned about.

### Changes

- **`/closeout` Step 2 requires exactly 40 hex characters (#184)** — the extraction regex tightens from `\{7,40\}` to `\{40\}`, so reader and writer now agree on one width. The prose branched on "the SHAs match" / "the SHAs differ" without ever saying which comparison it meant, so the check is now stated outright: exact string equality on two full OIDs, never a prefix test. A malformed marker no longer takes the interrupting "divergence" branch — it fails to parse, yields an empty `$REVIEWED_SHA`, and takes the honest "no stamp found" branch, which already degrades gracefully by design.
- **`/pre-merge` Phase 4 states the invariant beside the template (#184)** — `<full-sha>` and `<short-sha>` sit on adjacent lines in the block being substituted into, with nothing marking them as non-interchangeable. The bullet now says the HTML comment carries the full 40-character SHA and the short form belongs only in the visible prose line, and gives the reason: `headRefOid` is 40 characters, so a short SHA can never compare equal.
- **`scripts/test-review-currency-marker.sh` makes it mechanical (#184)** — the new suite **extracts** the real sed script from `closeout/SKILL.md` and the real marker template from `pre-merge/SKILL.md` rather than restating either, then round-trips one through the other. That is the design crux: a hand-copied regex in a test can drift alongside the thing it tests, whereas a suite that reads both halves fails precisely when they stop agreeing. Twelve assertions cover the round trip, rejection of 7/8/12/39-character and 41-character and non-hex markers, an unmarked body, and a duplicated stamp resolving to the newer SHA rather than the stale one. - **Prevention the repo had already written down (#184)** — `docs/solutions/architecture-decisions/staleness-gate-intermediate-writers-2026-08-06.md`, shipped *with* #163, named this class under Prevention → Code-level: "when a gate's contract spans two skills via a marker string, add a consistency check to the repo's existing test harness so the writer's emitted format and the reader's parser cannot drift apart silently. Absent that, a broken contract is indistinguishable from a legitimately un-stamped artifact — both take the no stamp found branch." The repo diagnosed the failure mode and shipped the contract without the check; this closes that gap.
- **Deliberately unchanged** — the gate's non-blocking character and three-outcome shape; the `/compound` false positive (#163's unremediated Concern, still tracked in the solutions entry); `SYSTEM-OVERVIEW.md`, which describes the loop's behavior rather than the marker's string format, and would be the wrong home for a width invariant. ## v1.19.0 — Review currency at the merge gate: `/closeout` checks that the approval still covers the diff (#163)

The pipeline reviewed a branch once and merged it later with nothing tying the two events together. `/pre-merge` read the diff and printed findings; `/closeout` merged the PR; in the intended linear flow those are the same diff, which is exactly why the gap was invisible. Real HITL sessions accrete scope on a branch *after* its review pass. On the triggering incident (a downstream client repo), `/pre-merge` passed a 29-line CI lockfile guard, then follow-on turns in the same session grew the branch roughly tenfold — a frontend test harness, a hand-rolled typed WebSocket fake, protocol tests, and a new dependency — none of it re-reviewed. A later manual read found two real defects in the un-re-reviewed code. The single review pass had silently certified an early subset of what was about to merge. Framed as "the operator forgot to re-run a skill" the fix is exhortation, which fails silently (Norman's blame reversal); framed structurally it is an inflow with no feedback loop — the same argument that produced `/closeout` itself, one seam over. Implements #163's Mediator "proceed narrowly" verdict.

### Changes

- **`/pre-merge` stamps the SHA it reviewed (#163)** — the PR body gains a `## Review Currency` block carrying an HTML-comment marker (`<!-- reviewed-at: <sha> -->`) for machines and a visible line for humans skimming the PR. Durable GitHub state, not a local file: a hook fires only in-session and would not survive the fresh `/closeout` session that typically does the merge (Norman — knowledge in the world, because prospective memory fails silently). Written at the **end of Phase 4** rather than at PR creation, which is a deliberate departure from the issue's suggested placement — the stamp asserts "a review completed at this SHA," so writing it in Phase 2 before the dimensions run would certify a review that had not happened. Phase 2 keeps a forward pointer so the PR-body mechanics stay discoverable. Reviewer-mode does not stamp: it never rewrites someone else's PR body, and its findings are unposted drafts with nothing reviewed in to certify.
- **`/closeout` Step 2 gains a review-currency precondition (#163)** — the three existing checkboxes asked whether a review happened, never whether it covered the diff about to merge. The new check reads the stamp, compares it to `headRefOid`, and branches three ways. Matching SHAs pass **silently** — announcing a non-event every run is what turns a gate into wallpaper. An absent stamp (hand-authored PR, external contribution, or a PR predating the stamp) is noted in one line and continues, because absence of a stamp is not evidence of an unreviewed diff and stopping on every un-stamped PR is the alarm fatigue that gets a gate reflexively defeated. A divergence prints `git diff --stat` and `git log --oneline` for the post-review delta, then asks once (re-review / acknowledge / stop) with re-review recommended.
- **Proportionality is the design crux, not a nicety (#163)** — the issue's Advocate and Skeptic both cite Meadows, and reconciling *add-the-missing-loop* against *policy resistance* is what the shape above is for. Showing the delta's **magnitude** rather than merely announcing that a delta exists is what makes the response proportional to a one-line typo fix versus a tenfold scope addition. A force-push that rewrote the reviewed commit out of existence is called out explicitly as a *stronger* divergence signal than a measurable delta, not a weaker one — the reviewed diff is simply unrecoverable.
- **Never hard-blocks (#163)** — `/closeout` stays HITL and non-blocking by design. The fix is making the divergence *visible*, not seizing the merge decision from the user. `/pre-merge` likewise stays advisory; it still does not set a formal GitHub `reviewDecision`.
- **`SYSTEM-OVERVIEW.md` records the loop (#163)** — Step 7.5's prose enumerates closeout's preconditions, so a fourth one that went unrecorded would leave the canonical overview describing a gate the skill no longer runs. Step 7's Output line names the stamp, and the Handoff Table's `/pre-merge` row reflects it. Bundled copies re-synced in the same commit: `SYSTEM-OVERVIEW.md` ships into four skills, and a partial edit is the #143 drift mode.
- **Deliberately unchanged** — not a hook and not an `init-pipeline` change (a local hook does not survive a fresh `/closeout` session); `/pre-merge`'s advisory nature; `/closeout`'s non-blocking character; and the two downstream defects that surfaced the incident, which map to existing `/pre-merge` dimensions and were skipped rather than missing.
- **Revisit if** — the check never fires across a sample of runs (the linear flow really does not accrete post-review → demote to an advisory line), or users always choose "merge anyway" on non-trivial deltas (behavior unchanged → move the trigger to the execute→pre-merge handoff, #115).
- **Unblocks #182** — that proposal's bounded review-response loop treats this stamp as a hard prerequisite, since scoping a re-review to the delta requires knowing which SHA the last review covered.

The fix makes `/execute` the single writer of that state and gives `/pre-merge` a reporting-only backstop — restoring the pack's GitHub-native state model for AC, where it had been leaking into an ephemeral channel.

### Changes

- **`/execute` Step 5 AC writeback (#102)** — after each acceptance criterion is confirmed verified, a forcing-function instruction ticks it in the slice issue body via `gh issue edit`. The instruction rides on the verification already performed (no new judgment) and edits narrowly: read the body, flip only the confirmed `- [ ]` lines to `- [x]`, write back via `--body-file`, never regenerate the body. The body file is created with `mktemp` and removed after the edit so two parallel worktrees or fast AFK Ralph iterations can't collide on a shared path and write back the wrong slice's body. `/execute` is named as the single writer.
- **`/execute` Step 6 AFK persistence (#102)** — AFK Ralph iterations skip the Step 5 user checklist, so a new line has them persist any AC verified during Step 4 before exit, using the same toggle. AFK is the mode that most needs at-a-glance legibility, and a Step-5-only placement would have left it uncovered.
- **`/pre-merge` Phase 4 reconciliation (#102)** — a reporting-only line: while slice issues are loaded, compare each `## Acceptance Criteria` checkbox state against what the merged diff and verification establish, and flag mismatches as factual notes. It explicitly does not write to the issue, preserving `/pre-merge`'s advisory identity and keeping `/execute` the sole writer.

### Motivation

The incident came from fulcrum: slice #235 of PRD #232 ran `/execute` → `/pre-merge` → `/ts-audit` with every acceptance criterion actually verified — grep-confirmed filter removal, 23/23 db-integration tests, clean `tsc` and biome — yet issue #235's five AC checkboxes were still unchecked after the work shipped. The verified status lived only in the chat transcript, and the user reasonably asked why the boxes weren't ticked. This is not "the agent forgot" (Norman's blame-reversal: a recurring omission is a design failure): structurally, `gh issue edit` appeared in zero skills, so AC verification state was produced and then thrown away. That contradicts `SYSTEM-OVERVIEW.md`'s state model — status that is neither code nor compounding knowledge is exactly what should live in GitHub. The `/improve-pipeline` dialectic landed at "Proceed narrowly": add the writeback to `/execute` only (Meadows' leverage point 6, missing information flows; Norman's knowledge-in-the-world via a forcing function bound to verification that already runs), with the Step 6 line so AFK runs are covered, and make `/pre-merge` report-only to avoid two writers contradicting each other on the same issue body. The Skeptic's body-corruption risk (`gh issue edit --body` rewrites the whole body) is met head-on by the toggle-only-`--body-file` mechanism plus the `mktemp` isolation. If telemetry later shows agents skipping the writeback under load (policy resistance), the named fallback is to promote it into a commit/merge hook (cf. #62) rather than grow the prose. Deliberately unchanged: `/prd-to-issues` authoring of the boxes, the Step 5 chat checklist as the HITL surface, and auto-close (`Closes` vs `Refs`) behavior.

Because `/help` dispatches its snapshot commands as a parallel tool-use batch in Claude Code, and because Claude Code cancels the in-flight siblings of any bash call that errors, a single bad ref killed the entire snapshot and forced a full retry.

### Changes

- **`/help` Step 1 split into Phase 1a and Phase 1b** — Phase 1a detects the base branch sequentially using `git symbolic-ref refs/remotes/origin/HEAD` with fallback through `main`, `master`, `prod`, `trunk`. Phase 1b dispatches the six read-only snapshot commands in parallel, each referencing the detected `$BASE_BRANCH`. If `origin/HEAD` is unset and no fallback candidate exists, the skill asks the user for the base branch name before continuing.
- **New "parallel tool-use gotcha" note in `/help`** — explicitly documents that one failing bash call in a Claude Code parallel batch cancels its siblings, and that this is why base-branch detection must run first and alone. Discourages the shortcut of chaining `&&`/`||` against a guessed branch inside a parallel batch.

### Motivation

Caught while running `/help` in the Civic Mirror repo (default branch `prod`). The initial state gather exited 128 on `git log main..HEAD`, which canceled the other six commands in the same parallel batch, and the recovery round had to retry everything with the correct ref. Two compounding problems: (1) the hardcoded branch name was wrong for the repo, and (2) the parallel dispatch amplified one failure into seven. Fix (1) addresses the immediate bug; fix (2) is a durable note so future skill authors know not to trust `&&`-chains inside parallel batches.

## v1.6.0 — BMAD Audit Adopts + /execute Auto-Flow + QA/Triage Restructure

Seven changes: five derived from the audit in `docs/bmad-comparison.md` against [bmad-code-org/BMAD-METHOD](https://github.com/bmad-code-org/BMAD-METHOD), a flow improvement that folds `/pre-merge` invocation into `/execute`'s existing manual verification checklist, and a restructuring of the bug path so `/qa` is the single entry point for bug conversations and delegates per-issue to `/triage-issue` when depth is needed. None of the seven changes the pipeline's core shape. Together they harden review, lower the friction of trivial changes, add the orientation and recovery affordances the pack was missing, remove the manual handoff step when the user is already at the PR-ready moment, and collapse two overlapping bug entry points into one.

### Changes

- **New skill: `/help`** — side-route orientation skill that reads current repo state (branch, open PRs, open issues, `research.md` presence, milestones) and recommends one next pipeline step with a one-line reason and the specific state signals that triggered it. Advisory only — never runs the recommended skill itself. Twelve-rule priority table covers the common pipeline states from "open PR on current branch" down to "clean slate, start with `/shape`."
- **New skill: `/correct-course`** — side-route recovery skill that turns the `SYSTEM-OVERVIEW.md` Pipeline Recovery prose into an invocable workflow. Captures the trigger, diagnoses which upstream skill's output is now untrustworthy, lists every stale artifact (`research.md`, PRD issue, slice issues, open PR, planning milestone), walks the cleanup one decision at a time, and hands off to the earliest affected skill with scoped re-run instructions.
- **`/pre-merge` minimum-findings guard** — Phase 4 now counts findings across all three tiers before presenting. If fewer than 4 surfaced on a non-trivial diff (>50 changed lines or >2 files), the skill does one more focused pass for common miss categories (scope drift, silent assumption changes, shallow modules, happy-path-only tests, new state files). Borrowed from BMAD's `bmad-review-adversarial-general` "at least ten issues" rule and tuned to our context — explicit anti-sycophancy guard that stops the review from closing too early.
- **`/execute` trivial-task exception** — Step 0 TDD classification gate now allows skipping classification via direct `.claude/.tdd-skipped` creation for single-commit cleanups (typo fixes, dead code removal, comment-only changes, formatting-only changes, dependency bumps without API changes). Guarded by four conjunctive conditions: not tied to a GitHub issue, not on an active feature branch, single commit, no behavior change. When any condition fails, use the normal gate.
- **`SYSTEM-OVERVIEW.md` handoff table** — new one-row-per-skill table added before the existing Default Handoff Map bullets. Covers all 23 skills with `Expects | Produces | Next` in ≤15 words per cell. Scannable orientation for readers who do not want to read the narrative bullets. Borrowed from BMAD's `module-help.csv` declarative flow model, adapted to markdown.
- **`/execute` → `/pre-merge` auto-flow** — Step 5's manual verification checklist now has a final "Ready for PR Review" item. When the user confirms it, Step 6 cleanup runs and `/execute` automatically invokes `/pre-merge`, passing the PRD issue number forward so slice lineage and boundary map contracts can be verified without re-asking. When the user answers "no" to the PR review item — batching with more work, waiting on external input, sitting on the branch — Step 6 runs cleanup and `/execute` exits cleanly for manual `/pre-merge` invocation later. AFK Ralph iterations and trivial-task flows that never reached Step 5 keep the prior clean-exit behavior. This is not from the BMAD audit — it came from observing that HITL users already run `/execute` → `/pre-merge` sequentially every time, so folding the transition into Step 5's existing user gate removes a redundant manual step without loosening the consent checkpoint.
- **`/qa` ↔ `/triage-issue` restructure** — `/qa` is now the single entry point for bug conversations and gains a new **Step 3.5 "Decide depth"** gate applied per issue. Lightweight issues (clear repro, obvious cause, uncontroversial fix) continue through the normal filing flow. Issues that fail the depth check — user explicitly asks for diagnosis, regression from working behavior, no confident hypothesis after Step 2 exploration, intermittent repro, or multiple symptoms possibly sharing an upstream cause — delegate to `/triage-issue` for that one bug. The triage issue replaces the lightweight issue `/qa` would otherwise have filed, and control returns to the `/qa` loop for the next observation. `/triage-issue` is recategorized from side-route to invoked helper and should no longer be called as a direct entry point. A single QA session can produce a mix of lightweight `/qa` issues and deep `/triage-issue` issues without the user having to pre-classify the whole batch.

### Documentation updates

- `README.md` — skill count 21 → 23, new "Orientation & Recovery" section with `/help` and `/correct-course`; `/triage-issue` description in the Development table rewritten to reflect per-issue invocation from `/qa`; `/qa` description in the Workflow table rewritten as the single entry point for bug conversations
- `SYSTEM-OVERVIEW.md` — side-route list, handoff map bullets, directory tree, and quick reference table all include the two new skills; new handoff table section above the existing bullets; `/execute` row in the handoff table and the `/execute → /pre-merge` handoff map bullet both note the auto-invocation; `/qa` and `/triage-issue` rows rewritten to describe the per-issue delegation and return-to-loop behavior; `/triage-issue` moved from side-route to invoked-helper list and from the SIDE ROUTES tree section up into the invoked-helper group; quick reference table collapses the prior two bug-path rows into "Run a QA session or report bugs" and "Investigate a specific bug deeply"
- `CLAUDE.md` — side-route list updated; `/correct-course` noted as the invocable front door for Pipeline Recovery; `/help` described as advisory orientation; new `/execute` key-interactions bullet describes the `/pre-merge` auto-invocation and which flows skip it; `/triage-issue` moved from side-route to invoked-helper category in Invocation Roles
- `docs/using-this-pack.md` — side-route list updated with descriptions; new "Start with `/help`" and "Start with `/correct-course`" entry points added; prior "Start with `/qa` or `/triage-issue`" entry rewritten as a single `/qa` entry with an explicit note that bug sessions should not start with `/triage-issue` directly
- `correct-course/SKILL.md` — "What This Skill is NOT" and "Do not use it for" sections updated so the bug-path redirect points at `/qa` only, noting that `/qa`'s per-issue depth check delegates to `/triage-issue` when root cause is needed

### Motivation

The audit against BMAD-METHOD (`docs/bmad-comparison.md`) surfaced twelve dimensions of comparison and cut the adopt list to the five highest-value items:

1. `/help` — BMAD's strongest idea this pack lacked. A router that reads state and tells you the next step makes every other pipeline investment more discoverable.
2. `/correct-course` — the Pipeline Recovery section of `SYSTEM-OVERVIEW.md` already documented backtracking, but it was prose. Turning it into a named skill gives it a front door.
3. Minimum-findings guard — `/pre-merge` was sometimes closing with two or three findings on large diffs because the agent found nothing obvious and stopped. A re-pass threshold hardens this cheaply.
4. Trivial-task exception — the TDD classification gate is load-bearing but creates friction on single-line cleanups. An explicit, guarded opt-out reduces the "pipeline is all-or-nothing" feeling without loosening the gate for real work.
5. Handoff table — BMAD's declarative `module-help.csv` is more scannable than narrative handoff prose for orientation. A markdown table gives most of that benefit without adding a CSV.

The audit also named five things deliberately not adopted (agent personas, filesystem-first state, story-level cadence, separate market/domain/technical research skills, post-hoc test generation) and five distinctive values to defend (mandatory research with Phase 0 version check, GitHub-native state discipline, compounding `docs/solutions/`, TDD classification gate, boundary maps before implementation). Those trade-offs are now durable in `docs/bmad-comparison.md`.

The sixth change — the `/execute` → `/pre-merge` auto-flow — is not from the audit. It came from observing the actual HITL workflow: the user was already running `/execute` followed by `/pre-merge` every time, so the explicit handoff was friction. Three options were considered: (A) auto-invoke with no prompt, (B) a separate Step 7 with its own confirmation, (C) fold the transition into Step 5's existing manual verification checklist as a final item. Option C won because it reuses the existing user-consent checkpoint instead of adding a new one, preserves the "the user decides when the PR happens" property, and naturally skips AFK Ralph and trivial-task flows where Step 5 does not run.

The seventh change — the `/qa` ↔ `/triage-issue` restructure — came from the same observation pattern. The prior model treated `/qa` and `/triage-issue` as two separate direct entry points for bug work, forcing the user to pre-decide whether a bug session was "lightweight intake" or "deep diagnosis" before starting. In practice most QA sessions mix both: three cosmetic bugs that just need filing, one regression that needs root cause, one intermittent failure that needs reproduction. Making the user re-enter a different skill mid-conversation was friction, and more importantly it meant `/triage-issue`'s depth was often skipped for bugs that silently needed it. Per-issue delegation from inside `/qa` lets a single conversation handle the mixed case without renegotiating scope. `/triage-issue` is still a distinct skill with its own rigor — it just stops being the thing the user reaches for directly.
